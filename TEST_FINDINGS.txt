## Why The Test Passes (Technical Explanation)

### 1. Mock Interception
The test patches at the import point:
```python

```

This intercepts the constructor call in `base_agent.py` line 351:
```python
self._agent_loop._search_service = InternetSearchService(user_id=self.user_id)
```

### 2. Mock Instance Receives Method
```python
mock_svc = mock_search_cls.return_value
mock_svc.search_financial_context = AsyncMock(...)
```

The mocked instance has the method ready to capture calls.

### 3. Real Call Path Reaches Mock
When `_execute_search_async` runs:
```python
res_list = await self._search_service.search_financial_context(
    query,
```

## Architecture Insight

The design uses a **parameter injection pattern** at the tool execution layer:

```
Generic Tool Layer
  (doesn't know about max_results)
         ↓
Tool-Specific Helper
  (injects max_results=3)  ← _execute_search_async
         ↓
Service Implementation
  (accepts max_results parameter)
```

This pattern ensures:
- Generic tool dispatch doesn't require parameter knowledge
- Tool-specific logic handles parameter defaults
- Service layer receives correct configuration
