## [Chinese] 產品規格與技術框架

### 1. 核心理念：混合分層架構 (Philosophy)

#### 1.1 評估報告結論
我們採用 **混合分層架構 (Hybrid Tiered Architecture)** 來平衡成本與深度。
*   **避免過度設計 (Avoid Overdesign)**: 不建立昂貴的全量索引。
*   **避免設計不足 (Avoid Underdesign)**: 不依賴純 OCR 文字分析，而是利用長文本模型的多模態能力進行精確解讀。
*   **策略**: **廣度篩選 (Screening)** 與 **深度即時分析 (Just-in-Time Analysis)** 的結合。

### 2. 混合分層架構 (Hybrid Tiered Architecture)

#### 2.1 第一層：訊號篩選 (The Signal Screen) - 廣度
*   **目標**: 利用結構化數據，從 3000+ 支股票中即時過濾出 50 支活躍標的。
*   **數據源**: Polygon.io (價格異動) + FMP (新聞標題)。
*   **邏輯**:
    *   價格突變 (Gap Up > 3%)。
    *   量能爆發 (Volume > 5MA * 2)。
    *   關鍵字觸發 (Earnings, FDA, Acquisition)。
*   **技術**: Websocket, Redis。

#### 2.2 第二層：事件評估 (The Event Assessor) - 過濾
*   **目標**: 過濾噪音，判斷新聞的「實質性」。
*   **數據源**: 新聞全文 API。
*   **模型**: 輕量級 LLM (GPT-4o-mini 或 Gemini Flash)。
*   **產出**: JSON `{impact_score: 9, sentiment: "Positive"}`。

#### 2.3 第三層：深度分析師 (The Deep Analyst) - 完整解讀
*   **目標**: 針對經過篩選的高價值目標，進行機構級的深度查核。
*   **數據源**: 原始 SEC 10-K/10-Q PDF。
*   **技術變革**: **Long-Context LLM (Gemini 1.5 Flash/Pro)**。
    *   **上下文完整性**: 直接將整份財報 (200頁) 作為 Context 輸入模型，確保不丟失層級結構與上下文。
    *   **多模態驗證**: 模型具備讀取複雜表格與趨勢圖的能力，能驗證文字描述的真實性。
    *   **功能**:
        *   **矛盾檢測 (Consistency Check)**: 比對 MD&A 樂觀文字與實際財務數據趨勢。
        *   **隱性關聯推導 (Implicit Relation Inference)**: 從模糊描述中推導供應商與客戶關係。

### 3. 數據源策略 (Data Source Strategy)
為了確保系統穩定性與成本效益，每種資訊目標皆配置 **主要 (Primary)** 與 **備援 (Backup)** 數據源。

| 資訊目標 (Info Goal) | 主要來源 (Primary) | 備援來源 (Backup) | 考量 (Considerations) |
| :--- | :--- | :--- | :--- |
| **股價 (Price)** | **Polygon.io** (付費) | **FMP (Financial Modeling Prep)** | Polygon 延遲低且穩定 (Tier 1 核心)；FMP 作為備案。若兩者皆掛，降級至 yfinance (不建議高頻使用)。 |
| **新聞 (News)** | **FMP** (付費) | **Google Search / NewsAPI** | FMP 專注財經新聞；Google Search 用於補足非財經但影響重大的事件 (如地緣政治)。 |
| **財報 (Fundamentals)** | **FMP / SEC API** | **Polygon.io** | FMP 解析度高；Polygon 資料庫亦完整。 |
| **總經 (Macro)** | **FRED (St. Louis Fed)** | **Yahoo Finance (^VIX, ^TNX)** | FRED 為官方數據源，最準確；Yahoo Finance 用於即時觀察市場情緒指標。 |

#### 3.1 成本與穩定性分析 (Cost & Stability)
*   **Polygon.io**: 成本較高 ($200/mo for effective WebSocket)，但提供最穩定的 WebSocket 連線。
*   **FMP**: 性價比高，適合作為靜態數據 (Financials, News) 的主要來源。
*   **Gemini 1.5 Flash**: 目前定價極具競爭力 ($0.35 / 1M tokens)，且 Context Window 夠長，無需 RAG 即可處理全份財報，大幅降低系統複雜度與向量資料庫維護成本。 


### 4. 技術實施路線圖 (Implementation Phases)

1.  **Phase 1 基礎建設 (Weeks 1-4)**: 搭建 FMP/Polygon 數據管道與 RabbitMQ 消息隊列。
2.  **Phase 2 長文本分析師 (Weeks 5-8)**: 整合 Gemini 1.5 API，實作 PDF 自動下載與分析 Worker。
3.  **Phase 3 Alpha 獵人 (Weeks 9-12)**: 實作關聯圖譜資料庫 (Neo4j) 與模擬交易回測。

## [English] Product Spec & Technical Framework

### 1. Core Philosophy: Hybrid Tiered Architecture

#### 1.1 Analysis Conclusion
We are adopting a **Hybrid Tiered Architecture** to balance cost and depth.
*   **Avoid Overdesign**: No expensive full-market indexing.
*   **Avoid Underdesign**: No reliance on pure OCR; utilize multimodal capabilities of Long-Context models for precision.
*   **Strategy**: A combination of **Broad Screening** and **Just-in-Time Deep Analysis**.

### 2. Hybrid Tiered Architecture

#### 2.1 Tier 1: The Signal Screen (Breadth)
*   **Goal**: Filter 3,000+ stocks down to 50 active targets instantly using structured data.
*   **Data**: Polygon.io (Price) + FMP (Headlines).
*   **Logic**:
    *   Gap Up > 3%.
    *   Volume Spike (> 5MA * 2).
    *   Keywords (Earnings, FDA, Acquisition).
*   **Tech**: Websocket, Redis.

#### 2.2 Tier 2: The Event Assessor (Filtration)
*   **Goal**: Filter noise; assess "Materiality".
*   **Data**: Full News API.
*   **Model**: Lightweight LLM (GPT-4o-mini / Gemini Flash).
*   **Output**: JSON `{impact_score: 9, sentiment: "Positive"}`.

#### 2.3 Tier 3: The Deep Analyst (Comprehensive Interpretation)
*   **Goal**: Institutional-grade audit on high-value targets only.
*   **Data**: Raw SEC 10-K/10-Q PDFs.
*   **Tech Pivot**: **Long-Context LLM (Gemini 1.5 Flash/Pro)**.
    *   **Context Integrity**: Feed the entire report (200+ pages) as context to ensure no loss of hierarchy or context.
    *   **Multimodal Validation**: Capable of reading complex tables and charts to verify text claims.
    *   **Features**:
        *   **Consistency Check**: Verify optimistic MD&A text against actual financial data trends.
        *   **Implicit Relation Inference**: Infer hidden supplier/customer relations from fuzzy descriptions.

### 4. Data Source Strategy
To ensure system stability and cost-efficiency, each information goal is assigned a **Primary** and a **Backup** source.

| Info Goal | Primary Source | Backup Source | Considerations |
| :--- | :--- | :--- | :--- |
| **Price** | **Polygon.io** (Paid) | **FMP** | Polygon offers stable low-latency WebSocket (Critical for Tier 1); FMP acts as backup. Fallback to yfinance if both fail (low frequency only). |
| **News** | **FMP** (Paid) | **Google Search / NewsAPI** | FMP focuses on financial news; Google Search complements with general macro events. |
| **Fundamentals** | **FMP / SEC API** | **Polygon.io** | FMP has high parsing quality; Polygon is a solid alternative. |
| **Macro** | **FRED** | **Yahoo Finance** | FRED is the official source; Yahoo Finance for real-time sentiment tickers (^VIX). |

#### 4.1 Cost & Stability Analysis
*   **Polygon.io**: Higher cost, but indispensable for stable real-time WebSocket data.
*   **FMP**: High cost-performance ratio, excellent for static data (Financials, News).
*   **Gemini 1.5 Flash**: Extremely competitive pricing ($0.35/1M tokens) with massive context window, eliminating the need for complex RAG pipelines for single-document analysis (like 10-K), reducing total cost of ownership.


### 5. Implementation Phases

1.  **Phase 1 Infrastructure (Weeks 1-4)**: FMP/Polygon pipelines & RabbitMQ.
2.  **Phase 2 Long-Context Analyst (Weeks 5-8)**: Gemini 1.5 integration & PDF Analysis Workers.
3.  **Phase 3 Alpha Hunter (Weeks 9-12)**: Relation Graph (Neo4j) & Paper Trading.
